# PR 5 agent evaluation: AGY subagents versus one Codex agent

Status: complete

Date: 2026-07-29

This is a one-PR engineering experiment, not a general model benchmark. Both
candidates started from the same frozen contract commit, `88f3565`, in isolated
Git worktrees. Neither candidate could see or modify the other's worktree. The
AGY candidate used three subagents; the Codex candidate used one implementation
agent with delegation disabled. The primary Codex session acted as evaluator.

## Experimental setup

| Candidate | Configuration | Wall time | Candidate result |
|---|---|---:|---|
| AGY | AGY CLI 1.1.8, Gemini 3.6 Flash High, high effort, three implementation/review subagents | 4m47s productive run; about 5m17s including the failed headless-permission attempt | rejected |
| Codex | one Codex implementation agent, no subagents | about 14m38s | accepted |

The AGY subagents split grammar/DFA, market clearing, and tests/contract review.
The Codex agent owned the complete change so that cross-module invariants had
one implementation owner.

AGY was about 2.8 times faster end to end. That speed did not convert into an
acceptable PR without substantial rework.

## Independent evaluator results

### AGY candidate

The candidate compiled and its reported native tests passed in clean debug,
release, and sanitizer builds. The evaluator observed 45 passing native cases.
It was rejected for these proven defects:

1. **Failure atomicity was violated.** `src/market/market.cpp` mutates accounts
   while applying accumulated deltas. A seller-cash overflow can therefore
   leave an earlier buyer mutated. An independent overflow probe returned 12,
   meaning account or last-tick state changed after the rejected batch.
2. **Tokenizer generation was not locked or reproducible from the contract.**
   `tools/grammar/generate_catalog.py` hard-coded an evaluator-specific `/tmp`
   tokenizer path, reimplemented part of the tokenizer instead of requiring
   `tokenizers==0.19.1`, and did not validate the locked byte size and SHA-256.
3. **The new Python tests were not discovered by the default suite.** Running
   the module directly found two tests, one of which errored because its call to
   `main()` consumed `unittest` command-line arguments.
4. **Strict formatting and repository hygiene failed.** The new C++ did not
   pass the checked-in clang-format gate, and the worktree contained an
   unignored sanitizer build plus Python bytecode.
5. **Several contract gates were weak or absent.** The DFA returned
   sentinels/empty spans for some invalid operations instead of typed failures,
   the property test used random samples instead of the frozen bounded
   exhaustive space, and the evidence document remained an unchecked
   blueprint.

The AGY worktree and branch remain uncommitted and were not integrated.

### Codex candidate

The evaluator independently rebuilt and tested the candidate from fresh build
directories:

| Gate | Evaluator result |
|---|---|
| Debug, release, ASan/UBSan | all three clean builds pass warnings-as-errors and CTest 2/2 |
| Native test cases | 50/50 pass |
| Default Python suite | 20 pass, one intentional opt-in skip |
| Locked-tokenizer suite | 3/3 pass |
| Catalog reproduction | 1,585 actions; generated bytes and SHA-256 are identical |
| clang-format and whitespace | pass |
| Independent seller-overflow atomicity probe | pass, exit 0 |

| Guarded PR 4 checkpoint regression | debug, release, and ASan/UBSan pass all 147,456 logits and exact greedy tokens |

The implementation was accepted as commit `00224a3`.

## Best combined operating model

Codex should remain the PR owner and final evaluator. AGY should be an optional
parallel specialist, not a required acceptance dependency:

1. Codex freezes the contract, assigns non-overlapping tasks, and owns stateful
   architecture and integration.
2. AGY subagents work read-only first: enumerate fault cases, audit the
   contract, propose exhaustive test matrices, and review generator
   reproducibility. These tasks benefit from parallel breadth and have little
   merge risk.
3. If AGY writes code, it writes only to a disposable worktree with a narrow
   `--add-dir`; it never shares the production branch with concurrent agents.
4. Codex evaluates candidate patches with fresh builds, deterministic
   regeneration, sanitizer runs, and adversarial probes that were not supplied
   to the generator.
5. Only Codex integrates and commits accepted changes. AGY findings are inputs,
   not acceptance evidence until reproduced.
6. The workflow must continue when AGY is unavailable. A planned read-only AGY
   review of the accepted candidate could not run because the account reported
   `Individual quota reached` with a roughly seven-day reset window.

For AGY permissions, prefer its documented allow/ask policy and sandboxed
directory scoping. `--dangerously-skip-permissions` was needed for this
disposable headless experiment after the normal request was auto-denied; it
should not be the default for a real integration branch. See the
[AGY CLI permissions documentation](https://antigravity.google/docs/cli/permissions).

The practical division is:

- **AGY subagents:** fast design breadth, adversarial test ideas, independent
  read-only review, and isolated prototypes.
- **Codex primary:** invariant-heavy implementation, cross-module consistency,
  deterministic acceptance, Git history, and final PR accountability.

This retains AGY's speed advantage without allowing quota, permission behavior,
or multi-agent integration gaps to determine whether the PR is safe.
