# PR 10 contract: synthetic radar workload

Status: accepted

Date: 2026-08-01

Base commit: `c3a4aaf`

## Outcome

PR10 added a deterministic 2D radar scenario, grammar-safe vehicle commands,
continuous-batch scheduling, shared-prefix KV accounting, deadline metrics, a
JSON trace, and a responsive browser replay. The current project keeps this as
a synthetic scheduler workload; it is not the inference runtime's public
identity or an end-to-end model client.

The prediction-market workload also remains as a regression target. Existing
`marketforge_*` targets retain the implementation namespace.

## Workload contract

- 32 vehicles and 6 moving tracks over 48 deterministic steps;
- noisy range/bearing radar generated by a fixed xorshift64* stream;
- five finite actions: `HOLD`, `INVESTIGATE`, `INTERCEPT`, `EVADE`, and
  `RETURN`;
- every action round-trips through the generic PR9 token DFA;
- every decision uses the PR8 round-robin scheduler with an eight-sequence
  batch cap;
- every sequence reserves paged KV memory against one immutable 64-token
  shared prefix and releases it on completion;
- the final cache must recover every physical page;
- trace output includes source configuration, radar returns, vehicle/target
  state, action validity, batch generation, latency, and deadline status.

## Measurement semantics

Scheduler latency is a deterministic virtual service-cost model, not a CPU or
GPU wall-clock timing. That makes deadline and fairness regressions exactly
reproducible across machines. The reported faster-than-real-time factor divides
simulated scenario duration by modeled inference service busy time.

CUDA and vLLM performance claims remain anchored to the accepted PR9
source-bound L4 artifact in `docs/pr9-modal-result.json`; PR10 does not change
the accepted CUDA kernels or model backends.
